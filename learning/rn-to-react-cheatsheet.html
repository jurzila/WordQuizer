WordQuizer · Expo 54 → Vite 8 + React 19

WordQuizer Migration Map

Every React Native construct in this codebase, and what it becomes on the web. Rows with a red edge look like a rename and aren't — the behaviour changes underneath.

React is a reconciler. It diffs element trees and has no idea what a screen is. The drawing is done by a renderer plugged in underneath — react-dom renders to DOM nodes, react-native to native view handles.

That single fact predicts the whole migration. Hooks, context, reducers, JSX and the component model sit above the renderer and port untouched. Primitives, styling, events, storage and navigation sit below it and get rewritten.

Primitives

The mechanical half. Most of these are a find-and-replace; the flagged ones aren't.

React NativeWebWhat actually changes
<View> <div> Nothing, structurally.
<Text> <p> <span> <h1> <label> Not one element — pick by meaning. A label above an input should be <label for>, which RN had no concept of. Text no longer has to be wrapped at all.
<TextInput> <input> <textarea> Inside a <form> it submits on Enter. That's a feature — but you must call preventDefault() or the page reloads.
<TouchableOpacity>
<Pressable>		 <button> A <button> inside a form defaults to type="submit". Anything that isn't the submit action needs type="button".
<ScrollView> <div> + overflow-y-auto Usually nothing — the page already scrolls. Only needed for a scrolling panel inside a fixed shell.
<FlatList> <ul> + .map() You lose virtualisation. Fine at a few hundred rows; not fine at ten thousand. This is the pagination conversation, deferred.
<Image source={{uri}}> <img src> resizeMode="cover" becomes CSS object-cover.
<Modal> <dialog> Native focus trapping and Esc-to-close, free.
<Switch> <input type="checkbox"> onValueChange → onChange, read e.target.checked.
<ActivityIndicator> — none — No built-in spinner. A CSS animate-spin ring, or nothing.
<SafeAreaView> env(safe-area-inset-*) Only matters for iOS Safari's home indicator. Often just droppable.
<KeyboardAvoidingView> — none — Mobile browsers handle it. Delete the component.

Props and events

Where most of the compile errors will come from, because the names are close enough to look right.

React NativeWebWhat actually changes
onPress onClick It bubbles. A click inside a clickable card fires both handlers unless you call stopPropagation().
onChangeText={t => …} onChange={e => …} You get an event, not a string. Read e.target.value. Easiest thing in the port to get silently wrong.
secureTextEntry type="password" Also unlocks password-manager save prompts.
keyboardType="email-address" type="email" Same mobile keyboard, plus free browser validation.
keyboardType="numeric" inputMode="numeric" Prefer inputMode to type="number" — no spinners, no scroll-wheel edits, no locale surprises.
editable={false} readOnly / disabled Two different things: readOnly still submits and still focuses, disabled does neither.
multiline <textarea> A different element, not a prop.
style={[a, b]} className="…" Array merge becomes string concatenation. Conditional styles want clsx or a template literal.
accessibilityLabel aria-label Often unnecessary — real semantic elements carry their own name.
testID data-testid Straight rename.
— none — autoComplete New surface with no RN analogue. Without autoComplete="email" / "current-password", password managers don't work. Users notice.
— none — htmlFor / id Also new. Wires a label to its input: screen readers announce it, and clicking the label focuses the field.

Layout defaults

Both use flexbox, so this looks like the easy part. It isn't — the defaults differ, and wrong defaults fail silently rather than erroring.

PropertyRN defaultCSS default → what to write
display flex, always block. justify-center and items-center do nothing until you add flex.
flexDirection column row. Every stacked RN layout needs an explicit flex-col.
flex: 1 on a root fills the screen Fills nothing — the parent has no height. Use min-h-screen or h-full.
text properties never inherit color, font-size, font-family and line-height cascade down. Set one on a wrapper and every descendant moves. RN has no cascade at all.
position relative static. An absolutely-positioned child anchors to the nearest positioned ancestor — so the parent needs an explicit relative.
numbers density-independent px Unitless CSS numbers mean nothing. Every value needs px or a Tailwind class.
shadow*, elevation two separate systems One box-shadow, or Tailwind's shadow-*.

StyleSheet → Tailwind v4

An RN style is an object of properties. A Tailwind class is one declaration. So one style object becomes a list of classes, roughly one per property — written at the usage site, not in a separate stylesheet module.

Declaring the palette

Tailwind v4 has no tailwind.config.js. Configuration moved into CSS. The --color- prefix is the contract: declare --color-primary and you get bg-primary, text-primary and border-primary generated for you.

ConcernThenNow
Palette theme/colors.ts @theme { --color-*: … } in index.css
Spacing scale theme/spacing.ts Built in. Tailwind's unit is 4px, so the class number is px / 4 — 16px is p-4.
Reusable styles sharedStyles.ts A component, or @apply. Not a style object.
Off-scale value any number Brackets: max-w-[400px], mt-[6px]
borderWidth: 1 one property Two classes. border sets width; the colour defaults to currentColor in v4, so without border-border you get a near-black line.

The worked example

{ flex: 1, backgroundColor: "#fafaf8", justifyContent: "center", alignItems: "center", padding: 16 }

min-h-screen flex flex-col justify-center items-center bg-background p-4

Five properties, seven classes. The two extras — flex and flex-col — are the RN defaults you never had to write. The min-h-screen is flex: 1 refusing to mean the same thing.

Platform APIs

Below the component layer. This is where the migration stops being mechanical.

React NativeWebWhat actually changes
AsyncStorage localStorage Async becomes sync. The largest single consequence in this codebase — it deleted a loading state, a module-level cache and a route-guard problem. Same 5MB-ish quota; both throw when the browser blocks site data.
React Navigation URL router An in-memory stack becomes the address bar. Params must serialise to strings; refresh and Back now work, and now have to be designed for.
Animated CSS transitions No Animated.Value, no interpolate, no createAnimatedComponent. A class swap plus transition-colors replaces the whole file — but onAnimationEnd replaces the completion callback, and it fires per-property.
Dimensions.get() CSS media queries Prefer sm:/md: classes over reading width in JS. matchMedia when you truly need it in JS.
Alert.alert() <dialog> window.confirm exists but blocks the thread and can't be styled.
Linking.openURL() <a href> Use a real anchor — middle-click, open-in-new-tab and copy-link all come with it.
expo-crypto crypto.randomUUID() Built into the browser. Secure contexts only (HTTPS or localhost).
process.env.EXPO_PUBLIC_* import.meta.env.VITE_* No process in Vite. The prefix is mandatory, and the variable must be renamed in Netlify too or the deploy silently uses the fallback URL.

Code that doesn't get ported — it gets deleted

A real share of any codebase exists to work around its platform. Change the platform and that code has no job. Budget for the migration shrinking the app.

Gone from WordQuizer

  • localStore.ts — was already dead; nothing imported it.
  • The let token module variable in api.ts — a synchronous cache in front of an asynchronous store. The store is synchronous now.
  • isLoading in useAuth — encoded "haven't finished reading storage yet". There is no such moment.
  • theme/spacing.ts — Tailwind ships a spacing scale.
  • theme/colors.ts — superseded by the @theme block, which becomes the single source of truth.
  • theme/sharedStyles.ts — utility classes replace style objects.
  • The three navigation/ files — file-based routes replace them.
  • Most of QuizCard.tsx — the Animated machinery is a CSS transition.

26 files in, roughly 20 out.

Problems you didn't have before

The web gives you refresh, Back, deep links and bookmarks for free. Free capabilities come with obligations.

Component identity

Navigating /lessons/abc → /lessons/xyz is the same component in the same tree position. React reconciles by position and type, not by props, so it keeps the existing instance and all its state — half-typed form fields included. Under React Navigation these were two stack entries and two instances, so the bug couldn't exist.

Fix: <AddWordForm key={collectionId} />. A changed key makes React unmount and remount, and state that has nowhere to live can't go stale.

Params have to survive a URL

These were plain JS objects in an in-memory stack:

{ collectionIds: string[], wordLimit: number | 'all', mode: 'word' | 'translation' }

A URL holds strings. ?collectionIds=a&collectionIds=b&wordLimit=all is the wire format, and parsing it back into those types is now your problem — TanStack Router's validateSearch is the place to put it. It also means a user can hand-edit the URL, so parsing has to reject nonsense rather than trust it.

State changes don't re-run route guards

Guards run on navigation. Setting token to null on logout doesn't move the browser anywhere — you have to navigate explicitly. The same applies after a successful login.

Everything a browser does that a phone didn't

  • Hover states now exist and need designing.
  • Text is selectable and right-clickable.
  • Enter submits forms; Escape closes dialogs; Tab order is real and needs to make sense.
  • The user can refresh mid-quiz. What happens to the deck?
  • Two tabs can be open on the same account at once.

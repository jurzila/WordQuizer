useEffect & useRef

escape hatches from React's render cycle

useEffect

run code after render

Syncs your component with something outside React — an API, a timer, local storage.

side effects async subscriptions 
useEffect(() => {
  // runs after render
  fetchData()

  return () => {
    // cleanup on unmount
  }
}, [dependency])
useRef

remember without re-rendering

Holds a mutable value across renders. Changing it never triggers a re-render.

mutable box DOM access flags 
const ref = useRef(false)

// read or write anytime
ref.current = true

// never causes re-render
dependency array

controls when it runs

// runs once on mount
useEffect(() => { ... }, [])

// runs when words changes
useEffect(() => { ... }, [words])

// runs after every render ⚠️
useEffect(() => { ... })
ref vs state

which one to reach for

// state — triggers re-render
const [loaded, setLoaded] =
  useState(false)

// ref — silent update ✓
const loaded = useRef(false)
loaded.current = true

how they work together — real example

const hasLoaded = useRef(false)   // silent flag

useEffect(() => {                     // load on mount
  getData().then((result) => {
    setWords(result ?? [])
    hasLoaded.current = true        // unlock saving
  })
}, [])

useEffect(() => {                     // save on change
  if (!hasLoaded.current) return    // guard ← why ref, not state
  storeData(words)
}, [words])

Why ref here, not state? If hasLoaded were state, setting it to true would trigger a re-render, which would re-run the save effect — exactly the race condition we're trying to prevent.

Order inside .then() matters. setWords first, then flip the ref — so saving is only unlocked after the loaded data is in state.

Conveyor-belt state & context

two real lessons from building a word-quiz app

state

the conveyor belt: one tap, four state updates

A correct match has to remove the word from view, pull the next one from a waiting pool, and reshuffle the translation column — all from one tap.

pool → visible (5) → matched 
if (selectedWord.id === item.id) {
  setMatched((prev) => [...prev, item.id]);

  let updated = quizWords.filter(
    (w) => w.id !== selectedWord.id
  );
  if (wordPool.length > 0) {
    updated = [...updated, wordPool[0]];
    setWordPool(wordPool.slice(1));
  }

  // derive once, write once →
  setQuizWords(updated);
  setTranslations(shuffle(updated));
}

Setters don't return values. const x = setState(...) gives you undefined — state updates aren't synchronous. Compute the new value as a plain variable first, then feed every setter from that same variable.

architecture

context: stop threading props through navigators

Adding nested screens meant every prop had to pass through layers that didn't use it — a navigator just forwarding data it doesn't care about.

// before — prop drilling through the tab screen
<Tab.Screen name="Words">
  {() => <WordListScreen
    words={words}
    onDelete={handleDeleteWord}
  />}
</Tab.Screen>
// after — the screen reaches in directly
<Tab.Screen name="Words" component={WordListScreen} />

// inside any screen, however deeply nested:
const { words, handleDeleteWord } = useWordApp();

Provider broadcasts, consumers tune in. One component high in the tree supplies the values; any screen below calls useContext to read them directly — no relay required at every level in between.

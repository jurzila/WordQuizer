useReducer

when multiple pieces of state always move together

state shape

one object, not many variables

before
useState([])    // pool
useState([])    // visible
useState(null)  // selected
useState([])    // matched
useState(false) // animating
after
type QuizState = {
  pool: Word[]
  visible: Word[]
  selected: Word | null
  matched: string[]
  isAnimating: boolean
}
actions

describe what happened, not what changed

type QuizAction =
  | { type: 'START_QUIZ'; payload: Word[] }
  | { type: 'SELECT_WORD'; payload: Word }
  | { type: 'CORRECT_MATCH'; payload: Word }
  | { type: 'WRONG_MATCH'; payload: Word }
  | { type: 'WRONG_ANIMATION_COMPLETE' }

Each action is a named event. The reducer decides what state changes — not the component.

reducer

pure function — given state + action, returns new state

function quizReducer(state: QuizState, action: QuizAction): QuizState {
  switch (action.type) {
    case 'CORRECT_MATCH': {
      const next = state.pool[0]
      const updated = [
        ...state.visible.filter((w) => w.id !== action.payload.id),
        ...(next ? [next] : []),
      ]
      return { ...state, matched: [...state.matched, action.payload.id],
               visible: updated, pool: state.pool.slice(1), selected: null }
    }
    default: return state
  }
}

Never mutate state directly. Always return a new object — spread ...state and override only what changed.

Compute derived values as local variables first, then return them together. Setters don't return values — you can't chain them.

usage

one hook, dispatch to change anything

const [state, dispatch] =
  useReducer(quizReducer, initialState)

// destructure what you need
const { pool, visible, matched } = state

// fire an action
dispatch({ type: 'SELECT_WORD', payload: item })
useState vs useReducer

when to reach for it

// useState — fine for independent values
const [name, setName] = useState('')

// useReducer — better when one event
// touches 3+ pieces of state at once,
// or logic gets hard to follow across
// multiple set() calls

Reducer logic lives outside the component — making it independently testable without rendering any UI.
